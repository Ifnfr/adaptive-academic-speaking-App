# Drill Mode Architecture

Last updated: 2026-06-19

This document describes the current Drill Mode architecture after Big-1,
Big-2, and Big-3.

## User Flow

Drill Mode lives inside Active Session as a sibling panel to Podchat.

1. Phase 0 - Pattern Brief
   - Generated through `POST /api/drill-session/start`.
   - Shows the target Pattern Brief before practice begins.
   - Includes focus, quality criteria, response pattern, mini example, and
     common mistakes.
   - This is the only phase where the full Pattern Brief is visible.

2. Internal Quick Check
   - Starts after the learner presses Start Drill.
   - Phase 0 content is removed from the DOM, not just hidden.
   - The learner speaks one short answer from memory.
   - The route can send the learner to Phase 1 or directly to Phase 3.

3. Phase 1 - Cold Recall
   - Collects baseline spoken responses.
   - It is baseline collection, not full pattern scoring.
   - Raw transcript is not displayed.

4. Phase 2 - Contrastive Repetition
   - Uses `/api/drill-session/turn`.
   - The learner repeats target ideas while the pattern reference stays hidden.
   - Partial/no-credit attempts trigger audio-first corrective feedback.
   - The corrective model uses `spokenModelFragment`, not the full pattern steps
     or the mini example.

5. Phase 3 - Pressure Test
   - Uses `/api/drill-session/turn`.
   - Shows a visual timer as a pressure constraint.
   - `startLatencyMs` is best-effort client timing from round start to
     recording start.
   - `pressurePassed` is separate from pattern credit. A learner can fail
     timing but still earn full pattern credit if the target pattern is present.

6. In-place Summary
   - Generated by `POST /api/drill-session/complete`.
   - Persists only at completion.
   - Shows bounded summary metrics and saved status.
   - New Session starts a fresh Drill Session from Phase 0.

## API Surface

`POST /api/drill-session/start`
- Authenticates through Clerk.
- Rejects owner/internal request fields.
- Generates a Pattern Brief with `spokenModelFragment`.
- Creates an in-memory `DrillSessionState`.
- Does not persist a session.

`POST /api/drill-session/turn`
- Authenticates through Clerk.
- Rejects owner/internal request fields.
- Accepts bounded session state plus a spoken transcript from STT.
- Supports Quick Check, Phase 1, Phase 2, and Phase 3.
- Phase 3 accepts validated `startLatencyMs` and derives `pressurePassed`.
- Does not persist a session.

`POST /api/drill-session/complete`
- Authenticates through Clerk.
- Rejects owner/internal request fields.
- Converts bounded `DrillSessionState` into completion metrics.
- Saves one bounded summary row to `pattern_drill_sessions` when Supabase is
  available.
- Does not store raw audio, raw transcript, raw provider payload, or prompt text.

Legacy Pattern Drill routes remain in the repo for compatibility and route
coverage. Big-2 and Big-3 active UI flow uses the Drill Session API.

## Audio Feedback

Drill Mode reuses the existing `/api/podchat/tts` route. It does not introduce
a new provider architecture.

Phase 2 partial/no-credit and Phase 3 corrective feedback are audio-first:

1. Short missing element.
2. Pause.
3. `spokenModelFragment`.
4. Pause.
5. Repeat instruction.

Visible fallback text must stay generic. During Phase 1-3 the UI must not show:

- raw transcript
- `spokenModelFragment`
- `responsePattern.steps`
- mini example
- common mistakes
- corrective model text
- long pattern reference

Repeat Feedback replays the last audio feedback. It does not call
`/api/drill-session/turn`, create a turn, change credit, change pressure
results, or persist anything.

## Persistence And Memory

Drill Mode is completion-only for persistence.

- Start, Quick Check, Phase 1, Phase 2, Phase 3 turns, TTS, Repeat Feedback, and
  discard do not save a final session.
- Completion writes a bounded summary to `pattern_drill_sessions`.
- `weaknessUpdate` is stored inside the bounded session summary only.

`learner_error_patterns` is not mutated by Drill Mode today. The existing
schema and active flow do not provide a safe owner-scoped weakness row update
path for completion-time mutation without a schema or contract change. Future
work may add this deliberately, but Big-3/Big-4 do not create migrations, add
tables, or modify `learner_error_patterns`.

## Boundaries

Current Drill Mode intentionally does not include:

- Convex
- schema changes
- migrations
- history page
- adaptive difficulty
- new weakness sources
- new TTS provider architecture
- Podchat behavior changes
- Weekly Review behavior changes
- Context Bridge AUR behavior changes
- deletion of legacy Pattern Drill routes
